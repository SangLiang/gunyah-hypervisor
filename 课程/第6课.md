# 第 6 课 · 入口汇编；MMU/TLS 没好之前不能进普通 C

L0 预备结束。本课开始跟源码，只解决两件事：**复位后真正进 Gunyah 的入口**；以及 **MMU / TLS 没好之前，为什么不能丢进普通 C**。`boot_cold_init` 里各模块订阅者是第 7–10 课。

---

## 1. 入口：平台 `head.S` → `aarch64_init`

以 QEMU 为例，平台汇编先跳进 EL2：

`hyp/platform/soc_qemu/src/head.S` 的 `__entry_el2` 末尾是 `b aarch64_init`。

然后进入 `hyp/core/boot/aarch64/src/init_el2.S` 的 `aarch64_init`。注释写明：Boot CPU 第一次上电进来时，**MMU 和 cache 是关着的**。

```asm
function aarch64_init, section=nosection
	msr	DAIFSet, 0xf          // 关 debug / abort / IRQ
	// 保存平台给的 PRNG seed、设 SCTLR_EL2、取 CPU 号
	bl	aarch64_init_kaslr
	bl	boot_rel_fixup
	bl	aarch64_init_address_space   // 开 MMU
	// 切到虚拟栈
	mov	x22, (1 << 63) - 1
	msr	TPIDR_EL2, x22        // 先塞一个非法线程指针
	bl	trigger_boot_runtime_first_init_event
	// 断言 TPIDR_EL2 已被改掉
	b	boot_cold_init
```

按顺序记：

```text
关中断 → 物理 boot 栈 → KASLR / 重定位 → 开 MMU
      → 虚拟栈 → 假 TPIDR → runtime_first_init（汇编里触发）
      → boot_cold_init
```

同文件另外两条入口，先知道名字即可：

| 函数 | 场景 |
|------|------|
| `aarch64_init` | Boot CPU 第一次上电 |
| `aarch64_secondary_init` | 其他 CPU 第一次上电 |
| `aarch64_warm_init` | 任意 CPU 从休眠 / 热插拔回来 |

## 2. 为什么还不能进普通 C

两件东西还没齐，普通 C 函数一进来就可能踩坑。

**MMU。** 进来时是关的。C 里的全局变量、函数指针，很多按**虚拟地址**编。页表没建、MMU 没开，这些地址对不上物理 RAM。所以先在汇编里 `aarch64_init_address_space`，再切到虚拟栈。

**TLS（Thread-Local Storage）。** 写法像全局变量（`_Thread_local`），实际是「先找到当前线程，再读它自己那一份」。找当前线程靠 `TPIDR_EL2`。汇编先写成非法值，再在汇编里触发 `boot_runtime_first_init`——这个事件会造出 Boot CPU 的 idle 线程并写好 TPIDR（第 9-12 课）。注释写得很直白：必须从汇编触发，好跟任何可能碰 `_Thread_local` 的代码隔开。

`boot.ev` 也写了：`boot_runtime_first_init` 跑的时候**没有当前线程**；handler 不能碰 TLS，也不能调 `cpulocal_get_index()`。

三件不要混：

1. **入口不是 `boot.c`。** C 侧总控是下一步；复位先进汇编。
2. **开了 MMU ≠ 可以随便写 C。** 还要有合法线程指针，TLS 才安全。
3. **不要去翻 `boot_cold_init` 的订阅者。** 那是后面几课。本课停在「汇编把运行时垫好，再 `b boot_cold_init`」。

---

## 本课你要带走的三句话

1. **入口**：平台 `head.S` → `aarch64_init`（开 MMU、垫运行时）→ `boot_cold_init`。
2. **MMU 关着进来**：虚地址还不能用，必须先在汇编里建地址空间。
3. **`boot_runtime_first_init` 必须在汇编里触发**：当时没有合法当前线程，普通 C 一碰 TLS 就会出事。
