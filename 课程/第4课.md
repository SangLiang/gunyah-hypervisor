# 第 4 课 · 中断和异常/陷入有何不同

上一课：虚地址靠页表落地；查不到会「出异常」。本课只解决一件事：**设备来的 IRQ** 和 **指令触发的异常/陷入** 不是一类。不讲 GICv3 寄存器，也不讲 VGIC 怎么注入给 guest。

---

## 1. 两种「CPU 被拉开去干别的」

CPU 正在跑指令时，有时必须停下、换到另一段入口代码。来路只有两类：

![中断与陷入](图/第4课-中断与陷入.svg)

| | 中断（IRQ） | 异常 / 陷入 |
|--|-------------|-------------|
| 谁发起 | **设备**（定时器、网卡、键盘…） | **正在执行的那条指令** |
| 时机 | **异步**：和当前指令无关，随时可能来 | **同步**：就卡在这一条上 |
| 例子 | 定时器到了、网卡收包 | 缺页、未定义指令、`HVC` / `SVC` |
| 直觉 | 外设按铃 | 这条指令自己要求换台阶，或根本做不下去 |

第 2 课说过：ARM 的「异常」是总称，换特权级都走固定入口。本课用操作系统习惯把总称拆开：

- 说 **中断**，特指设备来的 IRQ（异步）。
- 说 **异常 / 陷入**，特指指令触发（同步）。缺页是被动陷入；`HVC` 是主动陷入 EL2。

不要把 ARM 手册里「IRQ 也是一种 exception」和本课的拆法搅在一起。手册用总称；本课要的是 **来路不同**。

---

## 2. 都进向量表，后面不是同一条路

两类最后都跳到 **向量表**（CPU 按当前 EL 找的固定入口），也都可以换台阶：EL0 的 syscall 进 EL1，guest 的 `HVC` 进 EL2。相同的只有「进入口」；hyp 后面怎么处理，来路决定。

套回 Gunyah，先各记一句，跟代码是后面的课：

| 来路 | 以后哪一课展开 | 本课只要知道 |
|------|----------------|--------------|
| guest 执行 `HVC` | 第 25 课 | **陷入**进 EL2，是指令触发 |
| 物理设备的 IRQ | 第 22 课 | **中断**进 EL2，是设备触发 |
| 页表缺项 | 第 3 课已经见过 | **陷入**，不是网卡按铃 |

三件不要混：

1. **中断不是程序写错。** 设备正常工作就会来 IRQ。
2. **陷入 EL2 ≠ 中断进 EL2。** `HVC` 和物理 IRQ 都能到 Gunyah，但一条来自指令，一条来自设备。
3. **不要去背 GIC 寄存器、不要去想怎么注入 vIRQ。** 那是第 22–23 课。现在能指出「谁发起、同不同步」就够。

第 3 课的缺页落在右栏：MMU 查表失败，**当前这条访存指令**触发同步异常。定时器响了则落在左栏：即使这条指令完全合法，铃也会响。

下一节用两格入口代码看一眼表里放什么。不跟整份 `vectors.S`。

## 3. 向量表：固定入口，格子里是指令

向量表不是「发生了什么的说明书」，也不是第 3 课那张 **页表**。它只回答一件事：CPU 被拉开时，**从哪一段入口代码开始跑**。

顺序是反过来的：

1. **硬件先分类。** 已经知道这是 IRQ，还是这条指令卡住了（同步异常 / 陷入）。
2. **再按当前 EL 找到这张表的起始**，加上这一类的固定偏移，得到入口地址。
3. **从那个地址开始执行。** 格子里放的是入口指令，不是一排函数地址；入口再跳到真正的处理函数。

Gunyah 里这张表在 `hyp/vm/vcpu/armv8-64/src/vectors.S`。只看 guest 的两格，其余不必背：

```asm
vcpu_aarch64_vectors:                 // 表起始。CPU 按当前 EL 找到这里

vector vector_guest64_sync            // 陷入 / 同步异常这一格（HVC、缺页…）
	stp	x18, x30, [sp, #-16]!
	// …判断是不是 HVC，再进 exception_64_entry 等
vector_end vector_guest64_sync

vector vector_guest64_irq             // IRQ 这一格
	save_guest_context_vcpu_zero_0_13_irq   // 入口指令：先存现场
	b	irq_64_entry                      // 再跳到处理函数
vector_end vector_guest64_irq
```

IRQ 那一格最干净：格子里已经是要执行的指令。`b irq_64_entry` 才转到处理函数：

```asm
irq_64_entry:
	save_guest_context_vcpu_zero_14_29_irq
	bl	vcpu_interrupt_dispatch           // 真正处理中断
	b	vcpu_exception_return
```

所以：CPU 算出「表起始 + IRQ 偏移」之后，直接跑 `vector_guest64_irq` 里的指令，不是先从表里读出一个函数指针再跳。`HVC` / 缺页走另一格 `vector_guest64_sync`。同一张表，不同格，后面不是同一条路。

和页表对着记一句就够：

| | 页表（第 3 课） | 向量表（本课） |
|--|----------------|----------------|
| 对照什么 | 虚拟地址 → 物理页 | 「被拉开」→ 从哪段代码开始 |
| 格子里 | 描述符（页在哪、权限） | **入口指令** |
| 谁来用 | MMU 翻译访存 | CPU 换入口 / 换 EL 时跳进去 |

三件不要混：

1. **不是靠查表才知道发生了什么。** 类别硬件已经定了，表只提供对应入口。
2. **格子里是入口指令，不是一排函数地址。** 真正处理函数在入口再跳过去。
3. **不要通读整份 `vectors.S`、不要去背有几格。** 完整进 EL2 路径是第 22 课。现在能对着上面两格说出「固定入口、格里是指令、来路不同进的格也不同」就够。

---

## 本课你要带走的三句话

1. **中断是设备来的、异步的 IRQ**；和当前这条指令没有因果关系。
2. **异常/陷入是正在执行的指令触发的、同步的**（缺页、`HVC`、未定义指令都算）。
3. **两者都进向量表、都可能换 EL。** 表是固定入口（格里是指令，不是函数指针）；来路不同，进的格和后面处理也不同。
