# 第 2 课 · EL0 / EL1 / EL2 各跑什么

上一课定位了：Gunyah 是 Type-1，跑在 EL2；RM / PVM / SVM 都是它上面的 VM。本课只解决 **EL 这三个台阶各跑什么**。

---

## 1. 异常级别是特权台阶

ARM 把 CPU 的特权分成 **Exception Level（异常级别）**，缩写 EL。数字越大，能做的事越多：

![EL0 / EL1 / EL2 / EL3](图/第2课-异常级别.svg)

| 台阶 | 典型软件 | 权限直觉 |
|------|----------|----------|
| **EL0** | 应用程序 | 最低。不能直接碰硬件、不能改内核页表 |
| **EL1** | 操作系统内核 | 管本 VM 里的进程、驱动、本 VM 的页表 |
| **EL2** | Hypervisor（Gunyah） | 管有哪些 VM、VM 之间隔离 |
| **EL3** | 安全固件 / Monitor | 比 hypervisor 还高；本课不管，Gunyah 不跑在这里 |

「异常」在这里不是「程序出错」，而是 ARM 的术语：需要换特权级时，CPU 走一套固定入口（后面第 4 课、第 22 课会再碰到）。你现在只要知道：**EL 就是台阶，不是一种具体外设。**

同一颗物理 CPU **某一时刻只在其中一个台阶上**。跑 guest 时 CPU 在 EL1 或 EL0；要轮到 hypervisor(gunyah) 干活时，CPU 切到 EL2；干完再回到 guest。

---

## 2. 套回 Gunyah 的角色

把第 1 课的角色填进台阶：

| 软件 | 在哪个 EL | 原因 |
|------|-----------|------|
| 本仓库 Gunyah | **EL2** | 它就是 Type-1 hypervisor |
| Root VM 里的 Resource Manager | **EL1**（对这颗 CPU 而言是 guest） | RM 是第一个 VM，不是 hypervisor |
| PVM 里的 Linux 内核 | **EL1** | 主 OS，但仍是客户机内核 |
| PVM 里的 App（壳、浏览器…） | **EL0** | 普通用户态 |
| SVM 里的内核 / App | 同样 **EL1 / EL0** | 另一个客户机，台阶规则一样 |

三件不要混：

1. **RM 特权高，不等于它在 EL2。** 「策略上更特权」和「CPU 异常级别」是两件事。RM 向 Gunyah 要服务，自己仍在 guest 台阶。
2. **PVM 的 Linux 在 EL1，看起来像「普通手机内核」。** 对 App 来说它就是内核；对 Gunyah 来说它是被隔离的 VM。
3. **不要为了「记住 EL2」去背寄存器名。** 开了哪些控制位、VHE 细节，跟代码时再看。现在记住分工即可：EL0 跑 App，EL1 跑各 VM 的内核，EL2 跑 Gunyah。

Gunyah 默认用 ARMv8 的 VHE（Virtualization Host Extensions），含义只需一句：hypervisor 自己就在 EL2 上把活干完，guest 内核仍在 EL1。不必展开。

---

## 本课你要带走的三句话

1. **EL0 跑应用程序，EL1 跑某个 VM 的内核，EL2 跑 Gunyah。**
2. **同一颗物理 CPU 某一时刻只在一个 EL**；进 hypervisor 是切到 EL2，返回 guest 是回到 EL1/EL0。
3. **RM / PVM / SVM 都是 VM**：它们的内核在 EL1，不在 EL2。

## 小练习

请用自己的话回答下面两题（一两句就行）：

1. PVM 里的浏览器、PVM 里的 Linux 内核、Gunyah，分别在哪个 EL？
2. Resource Manager 是不是跑在 EL2？为什么？

回答：
1.浏览器是应用，跑在el0，PVM是primary vm ，是guest，应该跑在el1，只有gunyah，是跑在el2的
2.不是，host 就是 Gunyah 自己，它在 EL2，而是 RM 自己就是个 guest，它的内核在 EL1。

答完后，下一课只讲 **虚拟地址怎么落到物理页**（先只管 Stage-1，还不到 Gunyah 的 Stage-2）。
