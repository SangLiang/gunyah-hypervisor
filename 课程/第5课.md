# 第 5 课 · 线程是可调度实体；VCPU 也是一种线程

上一课分清了中断和陷入。本课只解决两件事：**调度器眼里可跑的是线程**；以及 **Gunyah 里的 VCPU 并不是另一套调度对象**。不讲 FPRR 队列，也不讲 `thread_switch_to` 怎么切栈。

---

## 1. 线程：调度器眼里「可跑的人」

一颗物理 CPU **某一时刻只执行一个控制流**。这个可被选中、可被换下去的控制流，叫 **线程**：自己有一份栈、一套被保存的寄存器，调度器可以把它从 CPU 上拿下来、过一会儿再放回去。

和第 2 课对着看：某一时刻只在一个 EL；某一时刻也只跑一个线程。EL 回答「现在用哪级权限」；线程回答「现在跑哪一段活」。

| 词 | 本课怎么用 | 先别往哪边滑 |
|----|------------|--------------|
| **线程** | 可调度实体：能占 CPU、能被换下 | 不是「Linux 的 pthread 教程」 |
| **进程** | 通常还带着自己的地址空间（第 3 课那张页表） | hyp 里不靠「进程」来调度 guest |
| **调度** | 决定下一颗物理 CPU 跑哪条线程 | 具体算法（FPRR）是第 15 课 |

没有线程这个词，CPU 就只是「一直往下跑」；有了它，才能说：这个跑完/被挡住，换另一个上来。

---

## 2. 在 Gunyah 里，VCPU 就是一种线程

第 1 课的 RM / PVM / SVM 是 **VM**。VM 自己不会「占住物理 CPU」——占住的是它的 **VCPU**。Gunyah 的调度器 **不认识虚拟机**，只认识线程。VCPU 是其中一种。

![线程与 VCPU](图/第5课-线程与VCPU.svg)

| 它 | 在调度器眼里 | 被切上去之后干什么 |
|----|--------------|--------------------|
| **idle 线程** | 仍是线程 | 没人可跑时待机（每颗物理 CPU 通常一条） |
| **VCPU 线程** | 同样是线程，种类不同 | 去跑某个 VM 的 guest（EL1/EL0） |

所以「跑 RootVM / 跑 PVM」不是另开一套虚拟机调度器，而是：**把那条 VCPU 线程调度到某颗物理 CPU 上**。种类只决定切上来之后走哪条入口；怎么排队、怎么切栈，本课不展开。

三件不要混：

1. **VCPU ≠ 另一套调度机制。** 它和 idle 走同一类对象：都是可调度线程。
2. **VM 是角色，VCPU 是跑在 CPU 上的那条线。** PVM 很「主」，仍要靠它的 VCPU 线程才能被切上去。
3. **不要去跟 FPRR 就绪表、不要去读 `thread_switch_to`。** 那是第 15–16 课。现在能说「调度器只调度线程，VCPU 是其中一种」就够。

和第 4 课的衔接只需一句：设备 IRQ 或 `HVC` 把 CPU 拉进 EL2 时，当前仍是 **某条线程** 在跑（常常就是那条 VCPU 线程）。谁该接着跑，仍由调度器在线程之间选。

---

## 本课你要带走的三句话

1. **线程是可调度实体**：物理 CPU 某一时刻跑其中一条。
2. **Gunyah 的调度器只认识线程**，不认识「虚拟机」这个类型。
3. **VCPU 是一种线程**；跑 guest 就是把这条 VCPU 线程调度到物理 CPU 上。
