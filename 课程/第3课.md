# 第 3 课 · 虚拟地址如何落到物理页

上一课把软件填进了 EL 台阶。本课只解决一件事：**程序手里的地址数字，怎样变成 RAM 上真正的位置**（Stage-1：VA → 页表 → PA）。

只记一个比方：**虚拟地址是软件自己编的门牌号**；**物理地址是 RAM 上真正的槽位**。中间靠**页表**对照。

---

## 1. 门牌号与物理槽位

CPU 读写内存时，指令里带的是一个数字。C 的指针、汇编里的地址，都是这个数字。

软件给自己编的一套编号叫 **虚拟地址（VA）**。芯片和总线认的 **物理地址（PA）**，才是 RAM 上的真实位置。

中间有一本对照，叫 **页表**：哪一段 VA 对应哪一段物理内存。CPU 靠它把门牌送到正确的 RAM 格。

每个进程有自己的一套门牌，这一套叫 **地址空间**。两个进程都可以有「自己的 `0x1000`」——编号碰巧一样，各自查自己的页表：

![两个地址空间](图/第3课-地址空间.svg)

读图时抓住一句：**CPU 拿到的永远是 `0x1000` 这个数字；落到哪块 RAM，取决于现在用哪张页表。**

用 VA 的两点好处：

1. **隔离**：各用各的门牌与页表；跑谁就装谁的表。App 日常使用 VA，由 MMU 完成翻译。
2. **连续假象**：程序侧内存可以排得整整齐齐；物理页由页表拼起来，可以散落在 RAM 各处。

---

## 2. 用 `0x1234` 走一遍：VA → 页表 → PA

页表映射的基本单位是 **页**，常见 **4KB**（`0x1000` 字节）：4096 个连续门牌算一组，页表里一格管这一整组。CPU 仍可以只读写其中 1 个字节。

一个 VA 拆成两截：

```text
VA = 页号 + 页内偏移
     ↑ 用来查页表，得到这一页的物理起始
     ↑ 页里的第几个字节，原样加到物理起始上
```

假设某次访存的 VA 是 `0x1234`，页大小 4KB：

```text
0x1234
  ├─ 页号：向下对齐到 4KB → 这一页从 VA 0x1000 开始
  └─ 页内偏移：0x234（这一页里的第 0x234 个字节）

查这个进程的页表：VA 页 0x1000 → 物理页起始 0x9A000
PA = 0x9A000 + 0x234 = 0x9A234
```

![VA 到 PA](图/第3课-VA到PA.svg)

程序侧写的是地址 `0x1234`；落到 RAM 上的是 `0x9A234`。

对照可以先想成：

```text
VA 页 0x1000  →  某块物理页起始
VA 页 0x2000  →  另一块物理页起始
…
```

一项管一整页：`0x1000` 和 `0x1234` 共用同一项；下一项才是 `0x2000`。

在 ARM64 上，**每一项固定 8 字节**：架构规定的描述符宽度，用来放下物理页号和权限等信息。

## 3. 扁平大表：问题是什么

若做成一张「页号 = 下标」的**扁平数组**，体积按下面算：

```text
表大小 ≈ (虚拟地址空间 ÷ 4KB) × 8 字节
```

「虚拟地址空间」指的是：**门牌最多能编到多宽**（MMU / OS 给出的 VA 容量）。

| 概念 | 它决定什么 |
|------|------------|
| 门牌宽度（如 32 位、约 48 位） | 扁平表按这个容量铺开 |
| 程序实际已映射多少 | 表里有多少项被填成有效 |
| 指针寄存器 64 位宽 | 一次能放下 64 位数字；MMU 常见翻译约 **48 位**门牌 |
| 物理 RAM 容量 | 机器上真正有多少可落脚的页 |

数量级（**门牌宽度** = VA 里参与编号的位数；宽度为 \(n\) 则门牌大约有 \(2^n\) 个）：

| 门牌宽度 | 空间容量（约） | 扁平表（约） |
|----------|----------------|--------------|
| 32 位（传统进程常按这档想） | \(2^{32}\) = 4GB | **约 8MB** |
| 约 48 位（ARM64 上 MMU 常见翻译这么多位） | \(2^{48}\)（很大） | **约 512GB / 进程** |

扁平表的核心问题：

1. **按全部可能的虚拟页预支空间。** 数组按下标连续铺开；无效项同样各占 8 字节。进程只用几 MB，目录仍按整段门牌容量收费。
2. **每个进程一份完整大表。** 隔离要求「各查各的表」；10 个程序就会有 10 张按全容量铺开的表，空坑重复付费。

门牌到约 48 位时，这份预支大约 512GB/进程，机器负担不起。

隔离本身靠的是：各进程各用各的页表，App 使用 VA、MMU 做翻译。扁平表要解决的是**体积与浪费**。

一句话：**大表按全部可能的门牌收费；程序按用到的门牌干活。**

## 4. 多级页表：机制是什么

多级页表把页号**拆成几段索引**，做成树。下面用两级说明（ARM64 常是 3–4 级，动作一样）：

```text
VA = 一级索引 + 二级索引 + 页内偏移
```

ARM64、页大小 4KB 时，**每一级表通常也是一本 4KB**：

```text
每级项数 = 4KB ÷ 8 字节 = 512
一本表大小 = 512 × 8 = 4KB
```

- **一级表**：某一格有效 → 写明「下一本二级表在哪」。某一格尚未使用 → 这一片地址尚未挂二级表。
- **二级表**：某一格有效 → 写明「这一页 VA 对应哪块物理页」。

`0x1234` 查法（MMU 硬件做）：

1. 打开本进程那本一级表，按一级索引找到格 → 得到某本二级表。
2. 打开该二级表，按二级索引找到格 → 物理页起始。
3. `PA = 物理起始 + 页内偏移`。

```text
扁平：按全部门牌容量先铺开全部表项
多级：先有一本一级；
      用到哪几片，就挂哪几本二级；
      一级某格尚未使用 = 对应二级尚未创建
```

![扁平表对比](图/第3课-扁平表对比.svg)

```text
VA = 一级索引 + 二级索引 + … + 页内偏移
      → 一级表[索引] 给出下一张表在哪
      → 最后一张表[索引] 给出这一页物理起始
      → PA = 物理起始 + 页内偏移
```

![查页表](图/第3课-页表查询.svg)

若两级、每级 512，一级 512 格**全部**挂上二级时：

```text
全部二级合起来 = 512 × 512 × 8 字节 = 2MB
```

一本二级是 4KB；2MB 是「二级全挂满」时的合计。多级省空间，靠的是**稀疏**：只为用到的地址挂二级。

### 一级、二级分别什么时候建？

| | 何时建立 | 多大 |
|--|----------|------|
| **一级** | **该进程 / 地址空间创建时**建立一本 | 通常固定 **4KB** |
| **二级** | 这个进程运行中，**第一次映射某片 VA** 时按需建立 | 每本 **4KB**，用到几片建几本 |

常见触发二级（以及填项）的时机：加载程序映射代码/数据/栈、`mmap`、堆变大、缺页且内核确认应补页等。

一级是这个程序的目录根，地址空间一创建就立好；二级是分册，映射扩到哪片门牌就盖哪本。

### 多级如何对上扁平表的问题

| 扁平的问题 | 多级的做法 |
|------------|------------|
| 按全容量预支、空段占坑 | 一级某格尚未使用 → 对应二级整本尚未创建；目录按实际映射生长 |
| 每进程一张完整大表 | 每进程仍有自己的页表；常用形态是「1 本一级 + 很少几本二级」 |
| 48 位容量预支过大 | 只为用到的地址分支建表，预支落在实际占用上 |

代价：每次翻译多查一两次表（MMU 做）。  
换来：目录跟着实际映射长。

## 5. 缺页：表上还没有这一项时

**查表由硬件 MMU 完成。** 内核负责把页表填对。

页表随运行更新。进程刚起来时，通常已映射代码、已有数据、栈的一小截；堆扩展等发生时，内核再往表里加项——需要二级时先建二级。

当前页表上没有对应项（或权限不够）时，CPU 发出同步异常——**缺页**。这条访存指令停在现场，CPU 进入内核事先登记的入口。

内核查看出问题的 VA，常见两条路：

1. **这块地址应当有映射，只是尚未落地。** 分配一页空闲 RAM，填好页表；缺中间层级就一并建好。
2. **这块地址非法。** 结束进程或向进程报错。

处理完成后，回到**原来那条指令再执行一次**。这是指令触发的同步异常；与设备触发的中断如何区分，下一课再讲。

本课范围是 Stage-1：查完得到物理页。有 Gunyah 时，Stage-2 在第 18–21 课。套回第 2 课：EL0 使用 VA；EL1 维护本 VM 的页表。

## 本课你要带走的三句话

1. **VA 是门牌，PA 是槽位**；扁平表大小按虚拟门牌宽度 × 每项 8 字节（ARM64 规定）来算。
2. **扁平表按全容量预支且每进程一份，体积与空段浪费大。** 多级把页号拆成索引：一级在进程创建时建好（4KB），二级按映射需要建立；目录按实际使用的地址生长。
3. **MMU 查表；缺项则缺页**，内核补表（含新建下级表）或判非法，然后重跑同一条指令。
