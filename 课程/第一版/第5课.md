# 第 5 课 · L2 内核基座：VCPU 线程如何被调度到物理 CPU

按学习地图：L1 已经把系统送到 idle；今天问一件事——**已经 `vcpu_poweron` 的 RootVM VCPU，是怎么被选中、切上物理 CPU、开始跑 Guest 的？**

> 本课目标：能用一句话讲清「VCPU 就是一种 `thread_t`」；能跟上 idle yield → FPRR 选中 → `thread_arch_switch_thread` → `vcpu_thread_entry` → ERET 这条路径；能说出 idle / VCPU_OFF / WFI 三种 block 各挡什么。

---

## 0. 先对齐：调度器不认识「虚拟机」

Gunyah 的微内核层只调度 **线程**。VCPU 不是另一套机制，它是 `THREAD_KIND_VCPU` 的 `thread_t`：创建、入队、切栈、TLS，全部走同一条调度路径。kind 只决定「被切上来之后跑哪个入口」。

![IDLE 与 VCPU](图/第5课-线程种类.svg)

| | Idle | VCPU |
|--|------|------|
| kind | `THREAD_KIND_IDLE = 1` | `THREAD_KIND_VCPU = 0`（刻意取 0，方便 `cbz`） |
| 创建时的 block | `SCHEDULER_BLOCK_IDLE`（永久） | `SCHEDULER_BLOCK_VCPU_OFF` |
| 进不进 runqueue | **不进**；队列空时硬回退 | `vcpu_poweron` 清掉 OFF 之后才进 |
| 入口 | `idle_loop` | `vcpu_thread_entry` → 直接 `exit_to_user` |

`thread_t` 不是一个 C 文件里写完的结构体，而是各模块用 `.tc` 的 `extend thread` 拼出来的：基础字段在 `hyp/interfaces/thread/thread.tc`，调度字段在 `scheduler_fprr.tc`，Guest 寄存器在 `hyp/vm/vcpu/vcpu.tc`。读代码时看到 `thread->scheduler_affinity` 或 `thread->vcpu_regs_el2`，就是这个拼装结果。

---

## 1. 线程怎么被造出来（对象链）

生命周期和 partition / memextent 一样：`object_init` → `object_create` → `object_activate`。

关键 handler（不必全记，抓住职责）：

1. **`thread_standard_handle_object_init_thread`**：写下 `thread->kind`。
2. **`thread_standard_handle_object_create_thread`（priority first）**：从 partition 分配内核栈；挂上 `SCHEDULER_BLOCK_THREAD_LIFECYCLE`（还没 activate，不许跑）。
3. **`scheduler_fprr_handle_object_create_thread`**：初始化 affinity、priority、timeslice、scheduler lock。
4. **VCPU 专用** `vcpu_handle_object_create_thread`：再挂 `SCHEDULER_BLOCK_VCPU_OFF`。
5. **activate（priority last）**：映射栈、`thread_arch_init_context`（PC = `thread_arch_main`）、`state = READY`、清掉 `THREAD_LIFECYCLE`。

对 VCPU：lifecycle 清了，**`VCPU_OFF` 还在**，所以 activate 完仍然不能跑。要等 `vcpu_poweron()`：

```c
// hyp/vm/vcpu/aarch64/src/aarch64_init.c
ret = scheduler_unblock(vcpu, SCHEDULER_BLOCK_VCPU_OFF);
```

清掉最后一位 block 之后，调度器才 `add_thread_to_scheduler`，按 affinity 挂到那颗物理 CPU 的 runqueue。需要的话再发 `IPI_REASON_RESCHEDULE`。

> 类比：造线程像办入职——填表（init）、发工位和工牌（create）、开通门禁（activate）。VCPU 多了一道「未上电」的门禁（`VCPU_OFF`）。`vcpu_poweron` 是按电闸；按了才能进当天的排班表（runqueue）。

## 2. FPRR：每 CPU 一张就绪表

实现：`hyp/core/scheduler_fprr/src/scheduler_fprr.c`。每颗物理 CPU 一个 `scheduler_t`（`CPULOCAL(scheduler)`）。

![FPRR 队列](图/第5课-FPRR队列.svg)

要点：

- 优先级 0…63，**数值越大越高**；默认 32。RootVM 用 `ROOTVM_PRIORITY`。
- `prio_bitmap` 64 位：哪一级有人就绪就置位。`bitmap_ffs` 找最高级。
- `runqueue[64]`：同级 FIFO。index `i = MAX_PRIO - priority`，所以最高优先级在最低 index。
- 时间片默认约 5ms；用尽且同级有人 → 轮转。
- 线程只进 **自己 affinity 那颗 CPU** 的队列。远程 unblock 靠 IPI。

`get_next_target()` 的决策：

```c
if (target != NULL) {
	scheduler->active_thread = target;
} else {
	target			 = idle_thread();
	scheduler->active_thread = NULL;
}
```

队列空时不是「选中 idle 并把它入队」，而是 **硬回退** 到 `idle_thread()`，并且 `active_thread = NULL`。idle 带着永久的 `SCHEDULER_BLOCK_IDLE`，这就是它永远不进 runqueue 的原因。

常用 API：

| 调用 | 行为 |
|------|------|
| `scheduler_yield()` | 当前 timeslice 置 0，再 `scheduler_schedule()` |
| `scheduler_block` | 置 block bit；不能跑了就出队 |
| `scheduler_unblock` | 清 bit；全清且可跑则入队 |
| `scheduler_trigger()` | 本地记一笔「需要重调度」（常配合 IPI） |

## 3. 真正切过去：`thread_switch_to`

`scheduler_schedule()` 要求 preempt disabled（它自己会 disable/enable）。选出 target ≠ current 之后：

```c
// hyp/core/thread_standard/src/thread.c
error_t
thread_switch_to(thread_t *thread, ticks_t schedtime)
{
	assert_preempt_disabled();
	trigger_thread_save_state_event();
	error_t err = trigger_thread_context_switch_pre_event(thread, schedtime);
	thread_t *prev = thread_arch_switch_thread(thread, &schedtime);
	// context_switch_post / load_state ...
}
```

`thread_arch_switch_thread`（`hyp/core/thread_standard/aarch64/src/thread_arch.c`）用一段内联汇编：

1. 把旧线程的 PC / SP / FP 存进 `old->context`
2. 装新线程的 SP / FP
3. 写 `TPIDR_EL2`（TLS 基址 → 新的 `current_thread`）
4. `br` 到新 PC

首次运行的新线程 PC 指向 `thread_arch_main`：

```c
static noreturn void
thread_arch_main(thread_t *prev, ticks_t schedtime)
{
	object_put_thread(prev);   // 这就是 idle 需要额外引用的原因
	thread_func_t thread_func =
		trigger_thread_get_entry_fn_event(thread->kind);
	if (thread_func != NULL) {
		preempt_enable();
		thread_func(thread->params);
	}
	thread_exit();
}
```

对 VCPU，`vcpu_handle_thread_get_entry_fn` 返回 `vcpu_thread_entry` → `vcpu_thread_start` → `thread_exit_to_user` → `vcpu_exception_return` → **ERET 进 EL1**。入口不做 `while(1)` 业务循环：这条线程「活着」的形态就是在 Guest 和陷入 hyp 之间来回。

## 4. 端到端：idle yield 选出 RootVM

第 4 课结尾：Boot CPU 进了 `idle_loop`，preempt 已解锁，RootVM VCPU 已在本 CPU 的 runqueue 上。

![idle yield 到 Guest](图/第5课-调度切换.svg)

`hyp/core/idle/src/idle.c`：

```c
static noreturn void
idle_loop(uintptr_t unused_params)
{
	preempt_disable();
	do {
		scheduler_yield();
		while (!idle_yield()) {
			// WFI / 等唤醒
		}
	} while (1);
}
```

逐步：

1. `scheduler_yield()` 把 idle 的 timeslice 清零并调用 `scheduler_schedule()`。
2. `get_next_target` 从 bitmap 里弹出 RootVM VCPU（优先级高于「空」）。
3. `thread_switch_to` → `thread_arch_switch_thread`：Boot CPU 的栈和 TLS 换成 VCPU 的。
4. 首次：`thread_arch_main` → `vcpu_thread_entry` → `exit_to_user` → ERET。
5. Guest 开始在这颗物理 CPU 上执行。

若 yield 回来了，说明队列空。`idle_yield()` 触发 `idle_yield` 事件（power 可能决定真的 WFI）；直到 IRQ / IPI 把某条 VCPU 重新入队。

## 5. 三把「不能跑」的锁

![三种 block](图/第5课-block位.svg)

`can_be_scheduled()` 看 `block_bits` 是否全空。本课先记住三个：

| bit | 谁挂上 | 谁清掉 | 含义 |
|-----|--------|--------|------|
| `SCHEDULER_BLOCK_IDLE` | idle 创建时 | **不清** | 待机线程，永不入队 |
| `SCHEDULER_BLOCK_VCPU_OFF` | VCPU 创建时 | `vcpu_poweron` / PSCI `CPU_ON` | Guest 还没上电 |
| `SCHEDULER_BLOCK_VCPU_WFI` | WFI trap | `vcpu_wakeup` | Guest 在等中断（第 7 课） |

还有 `THREAD_LIFECYCLE`（activate 前）等，本课不展开。

和第 3 课 preempt 的关系：

- `scheduler_schedule` / `thread_switch_to` **全程要求 preempt disabled**。
- idle 循环自己 `preempt_disable` 再 yield。
- 中断里若已经 disable，只 `scheduler_trigger()` 推迟；若可抢占，才直接 `scheduler_schedule()`。
- 进出 Guest：`thread_exit_to_user` 开头 disable，`thread_entry_from_user` 末尾 enable。

所以启动锁解开之后，也不是「随时随地乱切」：切线程的窗口是明确的（schedule 调用点、可抢占的 IRQ 返回前）。

---

## 本课你要带走的三句话

1. **调度 VCPU = 调度一种特殊的 hyp 线程**：FPRR 按 CPU 亲和性和优先级从 runqueue 取线程，不认识「虚拟机」这个词。
2. **idle 永不入队**：它带着永久 `BLOCK_IDLE`；队列空时 `get_next_target` 硬回退到它。`idle_loop` 的工作就是 `yield`，没人可跑就等。
3. **切上去之后 VCPU 入口直接 ERET**：`vcpu_thread_entry` 不是业务循环，而是 `exit_to_user` 进 Guest；陷入 hyp 再回到同一条线程。
