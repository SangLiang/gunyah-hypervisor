# 第 6 课 · L3 内存与隔离：一页物理内存如何进入 VM

按学习地图：线程已经能被调度了；今天跟 **安全隔离的核心**——一页 RAM 怎样从「属于某个 partition」变成「某个 VM 能通过 IPA 访问」。

> 本课目标：能分清 partition / memdb / memextent / addrspace 各自回答什么问题；能走通 7 步路径；能说出 `hyp_aspace` 和 guest `addrspace` 不是同一套页表。

---

## 0. 先对齐：四个角色，四个问题

文档里 **VMPhysAddr = IPA**。Guest 自己的 VA→IPA 是 Stage-1（Guest 内核管）；IPA→PA 是 Stage-2（Gunyah 管）。本课只跟 Stage-2 这一段。

![四个角色](图/第6课-所有权模型.svg)

| 概念 | 角色 | 它回答 |
|------|------|--------|
| **partition** | 资源会计 / 对象从哪分配 | 这页 PA 属于哪个分区？ |
| **memdb** | 全局 PA→owner 账本 | 这页 **当前** owner 是谁？ |
| **memextent** | 可映射的一段 PA（cap 可见） | 哪段 PA 能被 map 进 VM？ |
| **addrspace** | 一个 VM 的 Stage-2（含 VMID） | 这个 IPA 上映射了什么？ |

类型在 `hyp/interfaces/memdb/memdb.tc`：

```text
define memdb_type enumeration {
	NOTYPE = 0;
	PARTITION;
	ALLOCATOR;
	EXTENT;
	TRACE;
};
```

典型换主人顺序：RAM 加入 partition → `PARTITION`；进 heap → `ALLOCATOR`；activate memextent → `EXTENT`。**map 进 addrspace 不再改 memdb**——映射记在 memextent 的 mappings 和 Stage-2 页表里。

第 2 课的口诀仍然成立，只是多了两层：**partition 是持有者，memdb 是账本，memextent 是可捐赠的权证，addrspace 是 VM 看见的 IPA 世界。**

---

## 1. memdb：CAS 式换主人

接口（`hyp/interfaces/memdb/include/memdb.h`）：

```c
error_t memdb_insert(partition_t *partition, paddr_t start_addr, paddr_t end_addr,
		     uintptr_t object, memdb_type_t obj_type);

error_t memdb_update(partition_t *partition, paddr_t start_addr, paddr_t end_addr,
		     uintptr_t object, memdb_type_t obj_type,
		     uintptr_t prev_object, memdb_type_t prev_type);
```

实现上 **insert = 从 `NOTYPE` 做 update**（`hyp/mem/memdb_bitmap/src/memdb.c`）。update 要求整段连续属于 `prev_object/prev_type`，否则 `ERROR_MEMDB_NOT_OWNER`——不允许「这段里掺了别人的页还硬改」。

![memdb 换主人](图/第6课-memdb换主人.svg)

两个容易踩的点：

1. **`partition` 参数永远是 `partition_get_private()`**（给账本节点分配内存），不是「页的主人」。主人在 `object` / `obj_type` 里。
2. 第 2 课启动时：镜像先 `insert` 给 hyp partition，bootmem 再 `update` 成 `ALLOCATOR`；`partition_add_ram_range` 则 `insert` 给那个 owner partition。

> 类比：memdb 是土地登记处。insert 是「无主土地第一次办证」；update 是「过户」，且整块地必须已经在卖方名下。partition 参数是「登记处自己用的办公纸」，不是地契上的业主。

## 2. memextent：权证，activate 才过户

对外路径：

1. `partition_create_memextent` → 对象 `INIT`
2. `memextent_configure(me, phys_base, size, attrs)` —— **只填字段，memdb 仍是 PARTITION**
3. `object_activate_memextent` → `memextent_activate_basic`

```c
// hyp/mem/memextent/src/memextent_basic.c
error_t
memextent_activate_basic(memextent_t *me)
{
	if (me->device_mem) {
		ret = memdb_insert(..., (uintptr_t)me, MEMDB_TYPE_EXTENT);
	} else {
		ret = trigger_memextent_change_ownership_event(
			partition, NULL, me, me->phys_base, me->size);
		// 默认：memdb_update(..., EXTENT, partition, PARTITION)
	}
}
```

普通 RAM：PARTITION → EXTENT。设备内存：直接 insert（原先可能不在 partition 账上）。派生 extent 则是 parent EXTENT → child EXTENT。

**attach ≠ map**，不要混：

| 调用 | 进哪套页表 | 谁看见 |
|------|------------|--------|
| `memextent_attach` | `pgtable_hyp_map`（EL2 Stage-1） | hypervisor 自己 |
| `memextent_map` / `addrspace_map` | `pgtable_vm_map`（Stage-2） | Guest（经 IPA） |

attach 的 VA 必须来自 `hyp_aspace_allocate()`。info page 一类东西会 attach 给 hyp 写，但仍要再 `addrspace_map` Guest 才能看见。

basic 类型还有一个限制：`MEMEXTENT_MAX_MAPS = 4`，一个 extent 同时最多记 4 个 addrspace 映射。sparse 才支持按页拆分捐赠，本课先跟 basic。

## 3. addrspace：把权证写成 Stage-2 PTE

创建：`partition_create_addrspace` → `addrspace_configure(as, vmid)` → `object_activate_addrspace` → `pgtable_vm_init`（空的 Stage-2 根表 + 缓存好的 VTTBR 值）。`addrspace_attach_thread` 把 `thread->addrspace` 指过去。

Guest / RM 侧的 hypercall：

```c
// hyp/mem/addrspace/src/hypercalls.c
hypercall_addrspace_map(cap_id_t addrspace_cap, cap_id_t memextent_cap,
			vmaddr_t vbase, ...)
{
	// lookup 两个 cap（要有 MAP 权利）
	ret = memextent_map(memextent, addrspace, vbase, map_attrs, map_flags);
}
```

再往下：

```
memextent_map
  → memextent_map_basic          // 占一个 mapping slot
  → memextent_do_map
  → addrspace_map / addrspace_map_locked
  → pgtable_vm_map(..., stage = PGTABLE_VM_STAGE_2)
```

`vbase` 是 **IPA**，不是 Guest VA。PTE 写的是 IPA→PA + Stage-2 属性。

VCPU 被切上来时：

```c
// hyp/mem/addrspace/src/addrspace.c
addrspace_handle_vcpu_load_state(void)
{
	pgtable_vm_load_regs(&thread->addrspace->vm_pgtable); // MSR VTTBR_EL2
}
```

没有这一步，Stage-2 根表地址没装进硬件，Guest 访存会在 EL2 变成 abort。

## 4. hyp_aspace ≠ guest addrspace

![两套地址空间](图/第6课-两套地址空间.svg)

| | hyp_aspace | guest addrspace |
|--|------------|-----------------|
| 谁用 | Hypervisor EL2 | Guest VM |
| API | `pgtable_hyp_*` | `pgtable_vm_*` |
| 地址 | EL2 VA | IPA |
| 寄存器 | TTBR_EL2 | **VTTBR_EL2** |
| 直通 PA | `partition_phys_map`（physaccess 窗口） | 只能走 Stage-2 |

`partition_phys_map` 是 hyp 给自己开的「物理窗口」（VA = PA + offset），**不是**把页给 Guest。第 4 课 `copy_rm_env_data_to_rootvm_mem` 就是用这个窗口把 env 拷进 RootVM 的物理页。

同一页 PA 完全可以：hyp 用 Stage-1 attach 看见一份，Guest 用 Stage-2 map 看见一份。两套页表，两个观众。

## 5. 端到端：一页 RAM 的 7 步

![一页路径](图/第6课-一页路径.svg)

```text
[1] partition_add_ram_range
      → memdb_insert(..., owner_partition, PARTITION)

[2] partition_create_memextent + memextent_configure
      → 只填 phys/size；memdb 仍是 PARTITION

[3] object_activate_memextent
      → memextent_activate_basic
      → memdb_update(..., me, EXTENT, partition, PARTITION)

[4] 创建并 activate addrspace
      → pgtable_vm_init（空 Stage-2）

[5] hypercall_addrspace_map(as_cap, me_cap, ipa, ...)
      → memextent_map → addrspace_map → pgtable_vm_map

[6] Stage-2 PTE：IPA → PA
      memdb 不再改；映射在 extent + 页表里

[7] vcpu load_state 写 VTTBR_EL2
      guest VA →(S1, Guest) IPA →(S2, Gunyah) PA
```

有 children 的 extent 在第 5 步会 `memdb_range_walk`，只 map 仍属于自己的连续段。本课先按「整段 basic、无 parent」记。

## 6. 不要混淆的几件事

1. **configure 不换主人**，activate 才 `memdb_update`。
2. **memdb owner ≠ 已经 map 进 VM**。EXTENT 只说明「这页现在是这张权证的」；map 了没有看 mappings / 页表。
3. **partition 拥有 memextent 对象 ≠ 拥有那页 PA**。对象从 heap 分配；PA 所有权是 activate 时过户的。
4. **IPA ≠ Guest VA ≠ PA**。`addrspace_map` 的 `vbase` 是 IPA。
5. 本仓库的 `课程/第3课.md` 是 **L1 启动链第三段**，和地图上的 **L3 内存** 不是一回事。地图编号跟文件名错开，读的时候看标题。

---

## 本课你要带走的三句话

1. **memdb 记主人，extent 是权证，addrspace 写 Stage-2**：map 不改账本。
2. **activate 才过户**：`memextent_configure` 只填表；`memdb_update(PARTITION→EXTENT)` 发生在 activate。
3. **hyp_aspace 是 EL2 自己的 Stage-1**，和 VM 的 `addrspace`（VTTBR）不是同一套；`partition_phys_map` 只服务 hypervisor。
