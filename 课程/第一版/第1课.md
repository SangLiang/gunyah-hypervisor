## 第 1 课 · L1 启动链：从复位到 `boot_cold_init`

### 1. 真正的入口在哪？

平台汇编跳进 EL2 初始化。以 QEMU 为例：

`hyp/platform/soc_qemu/src/head.S` → `b aarch64_init`

然后进入 `hyp/core/boot/aarch64/src/init_el2.S` 的 `aarch64_init`：

```asm
function aarch64_init, section=nosection
	// Disable debug, aborts and interrupts.
	msr	DAIFSet, 0xf
	// ... 保存 PRNG seed、设 SCTLR_EL2 ...
	bl	aarch64_get_cpuid
	// ... 设物理 boot stack ...
	bl	aarch64_init_kaslr
	bl	boot_rel_fixup
	bl	aarch64_init_address_space   // 开 MMU
	// ... 切到虚拟栈、设假 TPIDR ...
	bl	trigger_boot_runtime_first_init_event
	// ...
	b	boot_cold_init
```

这一段在做的事，按顺序记：

![aarch64_init 从复位到 boot_cold_init](图/第1课-汇编启动.svg)

注释写得很清楚：此时 **MMU/cache 是关着进来的**；`boot_runtime_first_init` **必须在汇编里触发**，因为还没有合法线程指针，C 里碰 TLS 会出事。

> 关于TLS: TLS 是 Thread-Local Storage（线程局部存储）。每个线程各自一份、互不共享的变量。写法上常像“全局变量”，实际访问时要先找到当前线程，再读它自己的那份数据。
`_Thread_local int foo;   // 每个线程有自己的 foo`
要先在汇编里触发 boot_runtime_first_init，让运行时把 TPIDR_EL2 设好，后面的 C（含 boot_cold_init）才能安全碰 TLS。

同文件还有另外两条入口，先知道名字即可：

| 函数 | 场景 |
|------|------|
| `aarch64_init` | Boot CPU 第一次上电 |
| `aarch64_secondary_init` | 其他 CPU 第一次上电 |
| `aarch64_warm_init` | 任意 CPU 从休眠/热插拔回来 |

---

### 2. 事件总序：`boot.ev` 合同

接口定义在 `hyp/interfaces/boot/boot.ev`：

```text
event boot_runtime_first_init
event boot_runtime_warm_init
event boot_cpu_early_init
event boot_cold_init
event boot_cpu_cold_init
event boot_cpu_warm_init
event boot_hypervisor_start
event boot_cpu_start
```

**Boot CPU 冷启动**会把上面这条链（除 `boot_runtime_warm_init`）跑完；然后进 idle。注释还强调：这些事件跑完后，idle 循环**马上可能切到某个 VCPU**。

---

### 3. C 侧总控：`boot_cold_init`

文件：`hyp/core/boot/src/boot.c`

```c
noreturn void
boot_cold_init(cpu_index_t cpu) LOCK_IMPL
{
	// 设 stack canary（不能靠 event handler）
	__stack_chk_guard = ...;

	trigger_boot_cpu_early_init_event();
	trigger_boot_cold_init_event(cpu);
	trigger_boot_cpu_cold_init_event(cpu);

	// 到这里才能安全打日志
	TRACE_AND_LOG(... "Hypervisor cold boot" ...);

	trigger_boot_cpu_warm_init_event();
	trigger_boot_hypervisor_start_event();
	trigger_boot_cpu_start_event();

	thread_boot_set_idle();   // 不再返回
}
```

对应心智图：

![boot_cold_init 事件总序](图/第1课-cold_init总序.svg)

`trigger_boot_cold_init_event(cpu)` **不是只调一个函数**，而是按优先级调用所有订阅者，例如：`partition`、`memdb`、`pgtable`、`gicv3`、`irq`、`scheduler`… 这就是“模块拼装”。

---

## 本课你要带走的三句话

1. **入口**：平台 `head.S` → `aarch64_init` →（开 MMU + runtime）→ `boot_cold_init`。
2. **拼装方式**：`boot.ev` 定义事件；各模块 `subscribe`；`trigger_*` 按优先级广播。
3. **终点**：冷启动最后进 `thread_boot_set_idle()`，之后调度器才开始真正“跑系统”。

## 小练习

请用自己的话回答下面两题（一两句就行）：

1. 为什么 `boot_runtime_first_init` 必须在汇编里触发，而不能放到 `boot_cold_init()` 的 C 代码开头？
2. Boot CPU 冷启动时，`boot_cold_init` 事件和 `boot_hypervisor_start` 事件，哪个只跑一次、哪个更偏“全局数据结构初始化”？

回答：
1.因为当时 还没有合法的当前线程指针，而 普通 C 函数可能一进来就碰 TLS。
2.两个事件都只在 boot CPU 第一次上电时跑一次。boot_cold_init 更偏"全局数据结构初始化"（为后续 handler 能工作打地基）；boot_hypervisor_start 更偏"高层服务启动"（搭 root VM 运行时环境），位置更靠后。

答完后，下一课我们打开 **`boot_cold_init` 的几个关键订阅者**（`partition` / `memdb` / `thread`），看“模块拼装”在代码里长什么样。
