# 第 4 课 · L1 启动链收尾：`boot_hypervisor_start` + idle 交接 + RootVM

按学习地图：上一课跟完了 per-CPU 的 cold（建骨架）和 warm（通电）；今天打开 Boot CPU 才跑的「高层服务」阶段，看 **RootVM 怎么被造出来**，以及控制权怎么交给 idle。

> 本课目标：能说清 `boot_hypervisor_start` 只跑一次、谁先谁后；能区分 `idle_thread_init`（造对象）和 `thread_boot_set_idle`（跳进去）；能口述 RootVM 从 cspace 到 `vcpu_poweron` 的路径。

---

## 0. 先对齐：本课在启动链上的位置

`hyp/core/boot/src/boot.c` 的 `boot_cold_init()`：

```c
trigger_boot_cpu_early_init_event();
trigger_boot_cold_init_event(cpu);       // 第 2 课
trigger_boot_cpu_cold_init_event(cpu);   // 第 3 课
trigger_boot_cpu_warm_init_event();      // 第 3 课
trigger_boot_hypervisor_start_event();   // ← 本课主战场
trigger_boot_cpu_start_event();          // 第 3 课：preempt 解锁
thread_boot_set_idle();                  // ← 本课第 5 节：跳进 idle
```

`hyp/interfaces/boot/boot.ev` 写得很清楚：

```text
// Hypervisor startup; sets up high-level hypervisor services.
//
// This runs only once, on the first power-on for the boot CPU. It is mostly
// used for setting up the root VM's runtime environment.
event boot_hypervisor_start
```

和第 3 课的三条入口对照：

| 入口 | 是否跑 `hypervisor_start` | 结尾 |
|------|---------------------------|------|
| `boot_cold_init` | **是（仅 Boot CPU）** | `thread_boot_set_idle()` |
| `boot_secondary_init` | 否 | `thread_boot_set_idle()` |
| `boot_warm_init` | 否 | `thread_boot_restore_frozen()` |

读法：per-CPU 的骨架和硬件闸，每个核都要走；「造 RootVM、立全局服务」只需要 Boot CPU 做一次。Secondary CPU 醒来后直接进自己的 idle，等着被调度。

整条链此时仍被第 3 课的 `cpu_init` 启动锁锁着（`require_preempt_disabled`）。RootVM 就算 `vcpu_poweron` 了，也要等 `boot_cpu_start` 解锁、再进 idle 之后，才会真正被调上物理 CPU。

## 1. 优先级总表：谁先跑

事件生成规则（`tools/events/ir.py`）：未写 priority → **0**；排序键 `(-priority, handler名)`。所以 **数字越大越早**；`first` 最早，`last` 最晚。同为 0 的模块按 handler 名排。

本课要盯的三档：

| 顺序 | 优先级 | handler | 干的事 |
|------|--------|---------|--------|
| 1 | **100** | `partition_standard_handle_boot_hypervisor_start` | 把非 hyp 镜像占用的 RAM 捐给 root partition |
| 2 | 0 | `idle_thread_init`、各类 timer/pmu/vgic/smmu… | 补完 idle 对象、给 hyp 自己分配 hwirq |
| 3 | **last** | `rootvm_init` | 创建 RootVM 并 `vcpu_poweron` |

![boot_hypervisor_start 总序](图/第4课-hypervisor_start总序.svg)

读法：左边先把内存给够，中间把 hyp 自己的服务立起来，最后才造第一个 VM。RootVM 必须等这些齐了——它要用 root partition 的堆、要用已经 enable 的维护中断、要用完整的 idle 线程当调度回退。

> 类比：cold/warm 是把工地的水电和工位准备好；`hypervisor_start` 是「开张」——先把货架上的存货补足（RAM），再把店里的设备接通（hwirq / idle），最后请第一位客人（RootVM）进门。客人进门不等于开始用餐：还要等总闸推上（`boot_cpu_start`）、服务员就位（idle），调度器才会把客人领到座位上。

## 2. `priority 100`：把剩余 RAM 捐给 root

`hyp/core/partition_standard/partition.ev`：

```text
subscribe boot_hypervisor_start()
	// Run this early since it can add more heap memory
	priority 100
```

`hyp/core/partition_standard/src/init.c`：

```c
void
partition_standard_handle_boot_hypervisor_start(void)
{
	error_t err = platform_ram_probe();
	// ...
	for (index_t i = 0U; i < ram_info->num_ranges; i++) {
		// 跳过 hyp 镜像占用区间；
		// 其余 RAM → partition_add_ram_range(partition_root, ...)
	}
}
```

要点：

- Root partition **对象**在第 2 课 `boot_cold_init`（`priority last`）就已经创建了，那时只捐了一块启动堆。
- 这里是把平台探测到的整段 RAM（扣掉 hyp 镜像）登记进 root partition，走的仍是第 2 课的 `partition_add_ram_range` → memdb 插入。
- 排 `100` 是因为后面 RootVM 加载 package、建 addrspace、分配对象都要从这块堆里拿内存。堆不够，后面全会 `panic`。

## 3. 默认 0：idle 补全，以及 hyp 自己的 hwirq

### 3.1 `idle_thread_init`：把半成品补完

第 2 课讲过：Boot CPU 的 idle 线程在 `boot_runtime_first_init` 就用 bootmem 抠出来了，当时只做了部分 `object_init`，因为 allocator 还没有。

`hyp/core/idle/idle.ev`：

```text
subscribe boot_hypervisor_start
	handler idle_thread_init()
	require_preempt_disabled
```

`hyp/core/idle/src/idle.c` 的 `idle_thread_init()`：

```c
void
idle_thread_init(void)
{
	// 给所有 idle 栈划一段 hyp 地址空间（含 guard）
	virt_range_result_t stack_range = hyp_aspace_allocate(aspace_size);
	// ...
	for (cpu_index_t i = 0U; i < PLATFORM_MAX_CORES; i++) {
		if (!platform_cpu_exists(i)) {
			continue;
		}
		if (cpu == i) {
			idle_thread_init_boot(self, i);   // 当前 CPU：补 object_create
		} else {
			thread_idle = idle_thread_create(i); // 其他 CPU：正常 allocate
		}

		// 额外引用：thread_boot_set_idle 会从自己切到自己，
		// thread_arch_main 里 object_put(prev) 实际在放自己。
		(void)object_get_thread_additional(thread_idle);

		CPULOCAL_BY_INDEX(idle_thread, i) = thread_idle;
		object_activate_thread(thread_idle);
		assert(scheduler_is_blocked(..., SCHEDULER_BLOCK_IDLE));
	}
}
```

逐段拆解：

1. **划栈 VA**：每个 idle 要有自己的内核栈。现在 hyp_aspace 已经能用了（第 2 课 `boot_cold_init`），可以 `hyp_aspace_allocate`。
2. **当前 CPU vs 其他 CPU**：Boot CPU 那条半成品只补 `object_create`；别的核的 idle 走完整 `partition_allocate_thread`。
3. **额外引用**：注释写得很直白——`thread_boot_set_idle()` 是「从自己切到自己」，`thread_arch_main` 里会对 prev 做 `object_put_thread`。如果不先加一条引用，idle 会在刚启动时把自己释放掉。
4. **activate 之后仍是 `SCHEDULER_BLOCK_IDLE`**：idle **永不进 runqueue**。队列空时调度器硬回退到它（第 5 课细讲）。

这一步**还没有跳进 `idle_loop`**。对象齐了，执行流仍在 `boot_cold_init` 里往下走。

![idle 造对象与跳进去](图/第4课-idle补全.svg)

### 3.2 统一模式：给 hyp 自己分配 hwirq

同优先级 0 的一批模块，干的事长得很像：

```c
hwirq_create_t hwirq_args = {
	.irq    = PLATFORM_GICH_IRQ,              // 换成各自的 IRQ 号
	.action = HWIRQ_ACTION_VGIC_MAINTENANCE,  // 换成各自的 action
};
hwirq_ptr_result_t hwirq_r =
	partition_allocate_hwirq(partition_get_private(), hwirq_args);
object_activate_hwirq(hwirq_r.r);
irq_enable_local(hwirq_r.r);   // 或 irq_enable_shared
```

本课只要记住 **vgic 这一份**（第 7 课会用到）：

`hyp/vm/vgic/src/deliver.c`：

```c
void
vgic_handle_boot_hypervisor_start(void)
{
	hwirq_create_t hwirq_args = {
		.irq	= PLATFORM_GICH_IRQ,
		.action = HWIRQ_ACTION_VGIC_MAINTENANCE,
	};
	hwirq_ptr_result_t hwirq_r =
		partition_allocate_hwirq(partition_get_private(), hwirq_args);
	// activate ...
	vgic_maintenance_hwirq = hwirq_r.r;
	irq_enable_local(vgic_maintenance_hwirq);
}
```

这是 **hyp 私有 partition** 上的维护 PPI，用来回收 List Register、处理 EOI。它不是给 RootVM 用的 SPI 转发对象——那些要等 `rootvm_init` 事件里再建。

同类还有：VM timer、hyp arch timer、PMU、SMMU TCU。模式相同，本课不逐个展开。

## 4. `priority last`：`rootvm_init` 造出第一个 VM

`hyp/vm/rootvm/rootvm.ev`：

```text
subscribe boot_hypervisor_start
	handler rootvm_init()
	priority last
	require_preempt_disabled
```

必须 last：前面 RAM、idle、hwirq 都要齐。路径在 `hyp/vm/rootvm/src/rootvm_init.c`。

### 4.1 骨架：cspace + VCPU 线程 + master cap

```c
void NOINLINE
rootvm_init(void)
{
	partition_t *root_partition = partition_get_root();
	platform_add_root_heap(root_partition);

	// 1. 分配 / 配置 / 激活 root cspace（MAX_CAPS = 4096）
	cspace_t *root_cspace = partition_allocate_cspace(...).r;
	cspace_configure(root_cspace, MAX_CAPS);
	object_activate_cspace(root_cspace);

	// 2. 分配 root thread，配成 critical VCPU，绑到 Boot CPU
	thread_t *root_thread = partition_allocate_thread(root_partition, params).r;
	vcpu_configure(root_thread, /* critical = true */);
	cspace_attach_thread(root_cspace, root_thread);

	// 3. 给 root cspace 建 master cap：自己、partition、vcpu
	cspace_create_master_cap(root_cspace, ..., OBJECT_TYPE_CSPACE);
	cspace_create_master_cap(..., OBJECT_TYPE_PARTITION);
	cspace_create_master_cap(..., OBJECT_TYPE_THREAD);
	// CapID 写进 QCBOR env，不是指针
}
```

要点：

- RootVM 的「操作系统」稍后由 package 里的 Runtime + Resource Manager 扮演；hyp 这边先把 **对象和 capability** 备好。
- Guest 将只看到 CapID（第 8 课）。这里已经在实践这句话：env 里写的是 `cspace_capid` / `partition_capid` / `vcpu_capid`。
- `cspace_attach_thread`：这条 VCPU 线程之后做 hypercall 时，`cspace_get_self()` 拿到的就是这个 root cspace。

### 4.2 `trigger_rootvm_init_event`：各模块往环境里塞东西

骨架立好后广播 `rootvm_init`。关键订阅者：

| 优先级 | 模块 | 作用 |
|--------|------|------|
| 1 | vgic | 建 VIC、attach VCPU、为 SPI 建 hwirq cap 给 RM |
| 0 | `rootvm_package` | 解 GPKG，加载 Runtime + Application ELF，填 `entry_ipa` |
| 0 | addrspace | 建 RootVM 的 Stage-2 地址空间 |
| 0 | vcpu / timer / power / … | 环境字段 |

Package（`hyp/vm/rootvm_package/src/package.c`）校验 header `ident == 0x47504b47`（"GPKG"），加载两份 ELF：

- **Runtime**：先跑起来的环境，`elf_get_entry` → `hyp_env->entry_ipa`
- **Application**：通常就是 Resource Manager

hyp 不解析 DTB 去启动 Linux；它把 caps、空闲内存、入口 IPA 打进 env，拷进 RootVM 物理内存，然后把 PC 指到 Runtime。

### 4.3 上电：`vcpu_poweron`

```c
	object_activate_thread(root_thread);

	trigger_rootvm_init_late_event(...);  // vgic 映射 GICD/GICR 等到 IPA

	scheduler_lock_nopreempt(root_thread);
	bool_result_t power_ret =
		vcpu_poweron(root_thread, vmaddr_result_ok(hyp_env.entry_ipa),
			     register_result_ok(hyp_env.env_ipa), power_flags);
	trigger_rootvm_started_event(root_thread);
	scheduler_unlock_nopreempt(root_thread);
```

`vcpu_poweron`（`hyp/vm/vcpu/aarch64/src/aarch64_init.c`）做两件关键的事：

1. 把 Guest 入口写成 Runtime 的 `entry_ipa`，`x0` 写成 env 的 IPA。
2. **`scheduler_unblock(vcpu, SCHEDULER_BLOCK_VCPU_OFF)`** —— 这条 VCPU 线程创建时带着 `VCPU_OFF`，清掉之后才能进 runqueue。

此刻 Guest **还没开始跑**。preempt 启动锁还在，当前 CPU 还在 `boot_cold_init` 里。调度发生在下一节之后。

![rootvm_init 创建路径](图/第4课-rootvm创建.svg)

> 类比：`rootvm_init` 是把第一位客人的座位、菜单、房卡都准备好，并通知厨房「客人可以上座了」（unblock）。客人真正坐下，要等餐厅开门（preempt 解锁）且迎宾就位（idle 开始 yield）。

## 5. `thread_boot_set_idle`：跳进去，不再返回

`hypervisor_start` 返回后，`boot.c` 接着：

```c
trigger_boot_cpu_start_event();  // preempt 清 cpu_init（第 3 课）
TRACE(DEBUG, INFO, "entering idle");
thread_boot_set_idle();          // noreturn
```

`hyp/core/thread_standard/src/init.c`：

```c
noreturn void
thread_boot_set_idle(void)
{
	thread_t *thread = thread_get_self();
	assert(thread == idle_thread());

	thread_arch_set_thread(thread);
}
```

`thread_arch_set_thread` 丢掉当前引导栈上的执行态，`br` 到该线程的 `context.pc`。idle 的 PC 在 activate 时被设成 `thread_arch_main`，再按 kind 取入口 → `idle_loop`。

| | `idle_thread_init` | `thread_boot_set_idle` |
|--|-------------------|------------------------|
| 何时 | `hypervisor_start` 事件链中间 | 链结束 + `boot_cpu_start` 之后 |
| 做什么 | **创建/激活对象** | **跳转进 idle 入口** |
| 返回？ | 返回 | 不返回 |

`idle_loop` 里 Boot CPU 第一次还会 `trigger_idle_start_event()`（第 2 课见过：校验引导栈红区、把引导栈还给 hyp 堆）。然后：

```c
do {
	scheduler_yield();
	while (!idle_yield()) {
		// 没人可跑：WFI 等到 IRQ / IPI
	}
} while (1);
```

`scheduler_yield()` 会看到 runqueue 上已经有被 `vcpu_poweron` 解阻塞的 RootVM VCPU，于是切过去。L1 到这里结束：hypervisor 开始「跑系统」。

## 6. 把 L1 整条链收进一张图

![L1 启动链全景](图/第4课-L1全景.svg)

四个关键时间点（接第 2、3 课）：

1. **`boot_runtime_first_init` 结束**：有合法当前线程，能碰 TLS。
2. **`boot_cold_init` 结束**：partition / memdb / allocator / root partition 就位。
3. **`boot_cpu_cold_init` 结束**：CPU index 就位，可以 `TRACE_AND_LOG`。
4. **`boot_hypervisor_start` + `thread_boot_set_idle`**：全局服务与 RootVM 就位，调度器开始工作。

`boot_hypervisor_handover` **不在**这条冷启动路径上。那是以后把控制权交给另一个 hypervisor 时才显式 `boot_start_hypervisor_handover()` 触发的，本课记下名字即可。

---

## 本课你要带走的三句话

1. **`boot_hypervisor_start` 只在 Boot CPU 冷启动跑一次**：先捐 RAM（100），再补 idle / 分配 hyp hwirq（0），最后 `rootvm_init`（last）。
2. **造 idle ≠ 进 idle**：`idle_thread_init` 把对象补完整；`thread_boot_set_idle` 才 `br` 进 `idle_loop`（noreturn）。
3. **RootVM 上电不等于开始跑**：`vcpu_poweron` 只清 `VCPU_OFF`；真正被调度要等 preempt 解锁、idle `yield` 之后。
