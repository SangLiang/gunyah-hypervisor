# 第 7 课 · L4 中断虚拟化：物理 IRQ → VGIC → 回到 Guest

按学习地图：线程能调度、内存能 map；今天跟一条端到端路径——**物理中断进入 EL2，VGIC 把它写成 ICH_LR，再 ERET 回 Guest**。

> 本课目标：能背诵 Forwarded SPI 这一条链；能说明 Guest 看到的中断靠 ICH_LR/ICV，不是靠 `HCR.VI`；能说出 WFI 时 VCPU 线程如何睡着再被 `vcpu_wakeup` 叫醒。

---

## 0. 先对齐：为什么物理 IRQ 会进 EL2

VCPU 初始化时固定打开 `HCR_EL2.IMO/FMO/AMO`（物理 IRQ/FIQ/SError 改路由到 EL2），并且 **关掉** 软件假中断位 `VI/VF`：

```c
// hyp/vm/vcpu/aarch64/src/aarch64_init.c
HCR_EL2_set_FMO(&el2_regs->hcr_el2, true);
HCR_EL2_set_IMO(&el2_regs->hcr_el2, true);
HCR_EL2_set_AMO(&el2_regs->hcr_el2, true);
HCR_EL2_set_VF(&el2_regs->hcr_el2, false);
HCR_EL2_set_VI(&el2_regs->hcr_el2, false);
```

切到 VCPU 时 `vcpu_context_switch_load()` 会写 `HCR_EL2`，并把 `VBAR_EL2` 设成 `vcpu_aarch64_vectors`。

![HCR 把 IRQ 路由到 EL2](图/第7课-HCR路由.svg)

课上要点：**Guest 看到的中断靠 ICH_LR 呈现给 ICV，不是 hyp 在 HCR 上竖一根 VI 旗。** 物理设备来的 SPI，先被 EL2 认领，再由软件决定写哪条虚拟 LR。

本课只深挖 **Forwarded SPI**（硬件 SPI 已 `vic_bind` 为 `VGIC_FORWARD_SPI`）。VM timer 那种软件 `virq_assert` 是同一条 `vgic_deliver`，只是 `is_hw=false`。LPI/ITS、1-of-N 先不展开。

## 1. 进入 hyp：向量表

文件：`hyp/vm/vcpu/armv8-64/src/vectors.S`。

| Guest 入口 | 汇编 | C |
|------------|------|---|
| Sync（HVC/WFI/abort…） | `vector_guest64_sync` | `vcpu_exception_dispatch` |
| IRQ | `vector_guest64_irq` → `irq_64_entry` | `vcpu_interrupt_dispatch` |
| SError | `error_64_entry` | `vcpu_error_dispatch` |

IRQ 路径：

```asm
vector vector_guest64_irq
	save_guest_context_vcpu_zero_0_13_irq
	b	irq_64_entry
```

```asm
function irq_64_entry local
	save_guest_context_vcpu_zero_14_29_irq
	bl	vcpu_interrupt_dispatch
	b	vcpu_exception_return
```

若物理 IRQ 打在 hyp 自己身上（idle、preempt 开着），走 core 向量 → `preempt_interrupt_dispatch()` → 同样进入 `irq_interrupt_dispatch()`。认领物理中断的核心是同一份。

## 2. 认领物理中断：`irq_interrupt_dispatch`

```c
// hyp/vm/vcpu/aarch64/src/trap_dispatch.c
void
vcpu_interrupt_dispatch(void)
{
	thread_entry_from_user(THREAD_ENTRY_REASON_INTERRUPT);
	preempt_disable_in_irq();

	if (irq_interrupt_dispatch()) {
		(void)scheduler_schedule();
	}

	preempt_enable_in_irq();
	thread_exit_to_user(THREAD_ENTRY_REASON_INTERRUPT);
}
```

`irq_interrupt_dispatch()`（`hyp/core/irq/src/irq.c`）循环：

1. `platform_irq_acknowledge()` → `gicv3_irq_acknowledge()`，读 `ICC_IAR1_EL1` 拿到 INTID。
2. SGI → 当 IPI 处理，返回 `ERROR_RETRY` 再 ack 下一条。
3. 其它 → `trigger_irq_received_event(hwirq->action, ...)`。
4. handler 返回 **true**：hyp 自己处理完，`platform_irq_deactivate`。返回 **false**：转发给 Guest，**先别 DIR**（硬件 listed 的 SPI 要等 Guest EOI 再联动 deactivate）。

第 4 课分配的 `HWIRQ_ACTION_VGIC_MAINTENANCE` 走 true 那条；本课主路径 `HWIRQ_ACTION_VGIC_FORWARD_SPI` 常常返回 false。

事件接线（`hyp/vm/vgic/vgic.ev`）：

```text
subscribe irq_received[HWIRQ_ACTION_VGIC_FORWARD_SPI]
	handler vgic_handle_irq_received_forward_spi(hwirq)

subscribe irq_received[HWIRQ_ACTION_VGIC_MAINTENANCE]
	handler vgic_handle_irq_received_maintenance()
```

## 3. 注入：`virq_assert` → `vgic_deliver` → ICH_LR

```c
// hyp/vm/vgic/src/distrib.c
bool
vgic_handle_irq_received_forward_spi(const hwirq_t *hwirq)
{
	bool_result_t ret =
		virq_do_assert(&hwirq->vgic_spi_source, false, true);
	// is_hw = true → delivery state 带 hw_active
	return deactivate;  // 失败才 true（关掉这条 SPI）
}
```

`virq_do_assert`：找到 VIC 和目标 VCPU，组好 `assert_dstate`（edge / level / hw_active），调用 `vgic_deliver`。

`vgic_deliver`（`hyp/vm/vgic/src/deliver.c`）的决策：

- 已在某个 LR 里 → `vgic_redeliver`
- 有空 LR → `vgic_list_irq`，把这条 vIRQ **listed**
- LR 满了 → `vgic_flag_locked`（记在 search bitmap，可能开 NPIE 或发 DELIVER IPI）
- 需要时 `vcpu_wakeup` / `vcpu_wakeup_self`

写入 List Register：

```c
ICH_LR_EL2_base_set_HW(&status->lr.base, is_hw);
if (is_hw) {
	ICH_LR_EL2_HW1_set_pINTID(&status->lr.hw,
				  hwirq_from_virq_source(source)->irq);
}
ICH_LR_EL2_base_set_vINTID(&status->lr.base, virq);
ICH_LR_EL2_base_set_State(&status->lr.base, ICH_LR_EL2_STATE_PENDING);
if (to_self) {
	vgic_write_lr(lr);   // → gicv3_write_ich_lr
}
```

`is_hw=true` 时 LR 带着物理 pINTID，Guest EOI 可以联动物理 deactivate。软件源（VM timer）走 `is_hw=false`，靠 EOI 维护 trap。

![ICH_LR 与 ICV](图/第7课-ICH_LR.svg)

Guest 内核把 ICV_* 当成「自己的 GIC CPU interface」：`ICV_IAR` 认领 vINTID，LR 从 PENDING → ACTIVE → EOI 后 INVALID。Guest 不需要知道 EL2 写过 ICH_LR。

VIC / vic_base 一句话：**vic 是虚拟中断控制器对象；vic_base 是绑定 hypercall 的胶水；真正注入在 vgic。**

## 4. 整条链画出来

![Forwarded SPI 注入路径](图/第7课-中断注入路径.svg)

```text
Guest EL1 运行（HCR.IMO=1）
  → vector_guest64_irq → irq_64_entry
  → vcpu_interrupt_dispatch
  → irq_interrupt_dispatch → ICC_IAR1_EL1
  → irq_received[VGIC_FORWARD_SPI]
  → virq_do_assert(..., is_hw=true)
  → vgic_deliver → vgic_list_irq   // ICH_LR = PENDING
  → 必要时 vcpu_wakeup
  → thread_exit_to_user → vcpu_exception_return → eret
Guest 再进 EL1：ICV 看到 pending vIRQ，走 Guest 自己的 IRQ 向量
```

`vcpu_exception_return`（`hyp/vm/vcpu/armv8-64/src/return.S`）恢复 ELR_EL2 / SPSR_EL2 后 `eret`。这 **不是**「替 Guest 进中断向量」，而是回到 Guest；虚拟中断由 CPU interface 硬件再呈现给 EL1。若 Guest `PSTATE.I` 允许，它会马上走自己 VBAR 上的 IRQ handler，读 `ICV_IAR` 拿到 vINTID。

## 5. WFI：线程睡着，vIRQ 再叫醒

Guest 执行 WFI 会 trap 进 hyp（`HCR` 也管这个）。处理：挂 `SCHEDULER_BLOCK_VCPU_WFI`，`scheduler_yield`——物理 CPU 去跑别人或 idle。

```c
// hyp/vm/vcpu/aarch64/src/wfi.c
void
vcpu_wakeup(thread_t *vcpu)
{
	trigger_vcpu_wakeup_event(vcpu);
	if (scheduler_unblock(vcpu, SCHEDULER_BLOCK_VCPU_WFI)) {
		scheduler_trigger();
	}
}
```

`vgic_deliver` 在 `need_wakeup` 时就会走到这里。这和第 5 课的 block 位对上了。

![WFI 唤醒](图/第7课-WFI唤醒.svg)

WFI 陷入时 vgic 还会**主动**跑一遍 maintenance handler：可能有维护中断已经 pending 但还没投递，不处理的话 Guest 会「等一个永远不来的铃」。

## 6. 维护中断与上下文切换（够用即可）

第 4 课注册的 `PLATFORM_GICH_IRQ` 进来后，`vgic_handle_irq_received_maintenance()` 读 `ICH_MISR_EL2`：EOI 回收 LR、NPIE 时再塞 pending、Group enable 变化等。LR 就那么几条，Guest 疯狂 EOI / 新中断到来时靠它把软件队列和硬件 LR 对齐。

VCPU 线程被切走 / 切回时：

| 时机 | 函数 | 做什么 |
|------|------|--------|
| save | `vgic_handle_vcpu_save_state` | 读回 LRs / APR / ICH_HCR / ICH_VMCR |
| load | `vgic_handle_vcpu_load_state` | 写回整组，再 `vgic_do_delivery_check` |

物理 CPU 上同时只有一个 VCPU 的 ICH_* 是热的；切走必须存，切回必须装。这和第 5 课 `thread_switch_to` 的 save/load 事件是同一趟车。

**PSCI `CPU_ON`**（`hyp/vm/psci/src/psci_common.c`）不创建中断路径：它找到已有的 VCPU 线程，调 `vcpu_poweron` 清 `VCPU_OFF`。线程跑起来之后才会 load VGIC/HCR，才能收 vIRQ。对象创建发生在 RootVM/RM 配置阶段。

---

## 本课你要带走的三句话

1. **物理 IRQ 因 `HCR.IMO` 进 EL2**，hyp 用 `ICC_IAR1` 认领，再决定写 ICH_LR；Guest 用 ICV 看见 vIRQ。`HCR.VI` 在代码里是关的。
2. **Forwarded SPI 主路径**：`irq_received` → `virq_do_assert(is_hw)` → `vgic_deliver` → `ICH_LR.PENDING` → ERET。hyp 的 ERET 只是回到 Guest。
3. **Guest WFI = VCPU 线程 block**：注入时 `vcpu_wakeup` 清 `VCPU_WFI`，调度回来再 ERET。
